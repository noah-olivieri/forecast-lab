# RF-001 offline score baseline

RF-001 implements [the evaluation protocol](evaluation_protocol.md) without
downloads, holdout access, live jobs or changes to frozen baselines. The model
predicts expected team scores from league/home effects and regularized team
offense/opponent defense effects. Paired chronological residuals approximate
joint integer final scores. This is not a full game or overtime simulation;
integer support is broader than mechanically feasible football scores.

## Run an explicitly prepared input

For the first real reconstructed run, use the exact reviewed manifest/command
in [the evaluation-gate report](nfl_evaluation_gates.md). Real execution now
requires a versioned 2006–2023-only policy before reading game tables, reviewed
season-specific postseason evidence, and reconciliation of the completed-game
population plus the separate externally documented BUF–CIN no-contest. Optional
pre-2006 archive partitions cannot enter this first recipe. No real backtest has
been run; the example below is only the CLI shape, not an authorization.

```sh
PYTHON_DOTENV_DISABLED=1 UV_OFFLINE=1 uv run python -m lab.backtest.nfl_score \
  --manifest data/research/inputs/manifest.json --run-id development-001
```

This writes only a new `data/research/runs/development-001/` directory. An existing
run ID fails. The CLI has no holdout override, network option or tuning-grid
override. The default seeds/gates/grid/splits come from the protocol. Set
`PYTHON_DOTENV_DISABLED=1` for every test/example invocation; RF-001 itself does
not import the config loader or dotenv.

The Python API `run(manifest_path, output_root, run_id, run_seed=20261008)` permits
an alternate output root for local fixture tests; it refuses a `forecasts` path.
The CLI always uses the ignored research runs root.
The CLI seed is fixed at 20261008. The API permits alternative seeds only for
explicitly marked synthetic diagnostics; real runs reject them before creating
an output directory. This is an execution guard, not proof that a caller never
searched seeds outside the runner.

## Manifest and tables

Manifest schema version 1:

```json
{
  "schema_version": 1,
  "synthetic": false,
  "cohort": "reconstructed_scores",
  "partitions": [
    {
      "path": "schedules-2011.csv",
      "season": 2011,
      "role": "development",
      "kind": "schedules",
      "sha256": "REPLACE_WITH_ACTUAL_SHA256",
      "audit": {
        "season_isolated": true,
        "kickoff_and_label_coverage_reviewed": true
      }
    }
  ],
  "postseason_rule_metadata": {
    "2011": "REPLACE_WITH_REVIEWED_RULE_SOURCE_AND_VERSION"
  }
}
```

This illustration is not an audited input or runnable manifest. Include separate
`labels` partitions with their own hashes; each CSV/Parquet contains exactly the
one declared season. Seasons 2006–2023 use role `development`; optional 1999–2005
partitions use `baseline_warmup` and initialize only frozen probability models.
List every file explicitly with a relative path; do not point at an all-season
source or directory. Paths cannot be hidden, symlinked or escape the manifest
directory. Review partition isolation before running; post-read row checks
cannot undo reading a falsely declared holdout file.

| Table | Columns |
|---|---|
| Schedule revisions | `game_id, season, week, game_type, kickoff_ts_utc, home_team, away_team, location` plus vintage columns |
| Score revisions | `game_id, season, home_score, away_score, completed` plus vintage columns |
| Vintage columns | `revision_id, published_ts, first_seen_ts, fetched_ts, source_hash, availability_evidence, evidence_ref` |

Times must carry timezone offsets; serialization uses UTC with six fractional
digits and Z. Empty optional times are unknown. `completed` accepts exactly
native booleans, integer 0/1, or strings `true`, `True`, `1`, `false`, `False`, `0`.
Other spellings (including `TRUE`, `yes`, `1.0`), blanks and float values fail;
scores are nonnegative integers, with blanks remaining missing. Schedule tables
must not contain score columns. `game_type` is REG, POST, WC, DIV, CON or SB;
preseason is removed in audited input preparation. Location is Home or Neutral.
Franchise aliases OAK→LV, SD→LAC, STL→LA are versioned as `franchise-v1`.
Game IDs are opaque keys and cannot supply missing kickoff times.
Required core headers (including `revision_id`) are checked even in empty
partitions. Missing headers fail; a present but blank kickoff/team remains an
explicit exclusion with its week, game type and location retained.

One revision-order clock applies to the entire dataset: `published_ts` by
default for strict PIT, `fetched_ts` for reconstruction. The manifest can declare
`revision_clock` as either of these or `first_seen_ts`; the choice is recorded.
Multiple versions of one game require nonmissing, distinct timestamps on that
clock. Revision-ID text never resolves ambiguity. Different IDs cannot represent
the same `(season, canonical home, canonical away, kickoff)` physical game;
latest pinned schedules also reject overlapping games for a team within four
hours. Legitimate kickoff revisions retain the same ID and are not duplicates.

`strict_pit` requires evidence references linking each admitted schedule and score
revision to an audited receipt or public archive. The runner checks declared
times/evidence types and hashes; it does not authenticate those documents.
`reconstructed_scores` assumes pinned retrospective final schedules and labels
with a four-hour finish lag, flags reconstruction, and cannot claim historical
T−24h availability. Missing kickoff/team identities are exclusions, missing
labels remain unscored, and malformed/ambiguous input fails visibly.
`synthetic=true` requires every input row's `evidence_ref` to begin with
`synthetic://`. This catches accidental flag changes, but cannot authenticate
invented evidence or dishonest declarations. CSV/Parquet parsing consumes the
same in-memory bytes whose SHA-256 was verified, without reopening the path.

Real postseason inputs need season-specific rule metadata before applying the
no-final-tie constraint. Historical overtime mechanics are not fitted. A rule
source string is an audit reference, not an automated verification of its truth.
The first real execution instead requires structured entries with `season`,
`reviewed=true`, `no_final_ties=true` and nonempty HTTPS `sources`; the
[rules audit](nfl_postseason_rules.md) documents the actual authoritative evidence
and any historical continuity inference. Code checks declarations, not source
authenticity. Read-only loading of legacy preparation archives remains possible
without adopting an execution policy or calling any model.

## Saved artifacts

| Artifact | Purpose |
|---|---|
| `started.json` | Immutable initial config, source manifest and runtime/code provenance |
| `splits.json` | Whole-game warm-up, inner-only and outer assignments |
| `predictions.jsonl` | Saved raw grid forecasts, RF-001/fallback, league, frozen Elo/home-rate and fixed-half predictions; every miss/exclusion stays visible |
| `records/*.json` | Shared content-addressed game, label, observation and residual records; complete vintage metadata |
| `sequences/*.json` | Ordered immutable prefix nodes containing previous-root, record-reference and length |
| `fits/*.json` | Mean coefficients, actual cutoff and compact `training_root` reference, including mean-only warm-up fits |
| `banks/*.json` | Compact ordered residual-sequence root and count; residual records reference original mean fits/targets and current admitted labels |
| `samples/*.npz` | Exact 10,000 integer home/away pairs in PCG64 draw order |
| `probabilities/*.json` | Rows `[home_score, away_score, count, probability]` from those draws |
| `events.jsonl` | `predictions_saved` precedes `evaluation_released` for each game |
| `evaluation.json` | Post-save target labels/provenance and per-game losses/PIT seeds |
| `trial_ledger.json` | Nine-setting nested selection, current admissible inner labels, common games and yearly sensitivity |
| `metrics.json` | Outer/per-season/slice metrics, counts, calibration, paired CIs, Brier bounds and MC sensitivity |
| `exclusions.json` | Explicit missing schedule fields |
| `external_population_exclusions.json` | External no-contests outside the completed-game input cohort, without invented cutoffs or predictions |
| `manifest.json` | Completion status, chosen settings, prediction/split hashes and provenance |
| `failure.json` | Failed-run exception type; incomplete run is not a completed evaluation |

Artifact schema is `rf001-v2`. JSON record/sequence/fit/bank filenames use SHA-256
of canonical JSON without the trailing newline. Histories share prefix nodes;
revised observations create new suffixes without overwriting earlier records.
`reservoir_hash` now hashes the bank descriptor, whose root transitively pins all
ordered residuals. Identical draw arrays share compressed samples and probability
tables; the sample filename hashes dtype, shape and raw-array hash, whereas
`samples_hash` pins the actual NPZ bytes. Each forecast retains its own cutoff,
seed, target schedule reference and summary. Identical RF-001/league fallback
distributions share one MC sensitivity check listing both model names.

Use `lab.backtest.score_artifacts.read_observations(run_path, training_root)` and
`read_bank(run_path, bank_path)` to verify hashes and reconstruct ordered inputs.
Refit with the saved penalty, half-life, league flag and cutoff (use the default
penalty for a league fit, whose saved penalty is null and unused); original means
can be recomputed against each residual's `fit_schedule_ref`, then combined with
its `label_ref` to reconstruct residuals. The regression test performs this
replay through all 50 bank entries and regenerates the saved forecast draws.
Provenance includes all RF-001 sources, frozen baseline sources and `store/asof.py`,
the alias version, dependency versions, NumPy's BLAS/LAPACK build metadata, lock
hash and dirty working-file hashes. Unknown vendor versions remain unknown.
Failures during writer initialization or later initialization/evaluation are
recorded, including `KeyboardInterrupt`, and re-raised. A physically unwritable
disk cannot guarantee a failure record; existing run directories are never
modified on refusal.

Draw means can differ from clipped regression means after residual centering,
rounding, clipping and postseason tie conditioning. Probabilities, margins,
totals and intervals all reconcile with the same saved samples. The distribution
retains regular-season ties; primary probability is home-result share,
`p_home + .5*p_tie`. That is not a prediction-market winner-contract probability.
Frozen baselines retain their original math; no native CRPS or three-way losses
are invented for them. Odds are not supplied by this runner, so market-mid
comparisons are unavailable.

Bootstrap intervals condition on saved forecasts and omit tuning uncertainty.
They resample entire football weeks in pairs, using actual replicate game counts.
Sparse slices/seasons can have degenerate intervals. Synthetic metrics test the
machinery and never establish historical accuracy or a trading edge.
Eligible counts include misses and unlabelled forecasts, but exclude input
exclusions; scored counts and paired common-game IDs are separate. PIT reports
retain per-game values and ten fixed equal-width bins, including 0 and 1.

## Reproduce the synthetic example

The invented fixture has 156 warm-up games among T0–T3 in 2011, then two games
per year in 2012–2016. It deliberately has tiny inner/outer folds. The generation
functions live in `tests/rf001_fixtures.py` and `tests/test_rf001_runner.py`.
After installing the pinned development environment:

```sh
PYTHON_DOTENV_DISABLED=1 UV_OFFLINE=1 uv run python - <<'PY'
import sys
from pathlib import Path
sys.path.insert(0, "tests")
from test_rf001_runner import experiment, manifest
from lab.backtest.nfl_score import run
schedules, labels = experiment()
input_path = manifest(Path("data/research/inputs/rf001-synthetic"), schedules, labels)
print(run(input_path, run_id="rf001-synthetic-example"))
PY
```

The run ID must be new (change the illustrated ID if it already exists).
Fixture receipts/source hashes are invented and the
manifest declares `synthetic=true`. No real NFL outcomes are used. Refer to
`rf001_synthetic_example.json` for the preserved **legacy v1** example, using the
old penalty grid. Current runs use v2 and the amended grid `{.0003,.001,.003}`;
the old example does not report current-grid results. See [the review response](rf001_review.md)
for synthetic recovery and bounded storage/runtime measurements.

## Real data remains a separate next task

No eligible real research manifest was present during implementation. Prior
256-row source prefixes prove sampled field availability only; they do not prove
full-season completeness, postseason labels or historical publication times.
Before a real run, prepare explicitly authorized through-2023 season-isolated
local schedules and completed labels, audit missing times/results/identity joins,
pin source hashes and postseason rules, and review each strict evidence reference
if requesting strict mode. Report actual cohort/fold coverage and any amendment
before fitting. Do not use an nflreadpy loader that fetches all seasons first.

The score-only baseline can use timely public prior scores in prospective use,
subject to archiving receipts and schedule revisions. A proven strict historical
archive is still missing. Player/scheme factors, timely detailed charting and
historical T−24h odds remain outside RF-001 and subject to the inventory's gaps.
Fits and frozen Elo still replay prior observations at every cutoff; computation
is not linear in historical game count. Append-only histories share storage,
but many genuine revisions can create extra immutable suffixes. Full 2006–2023
runtime, storage and cross-BLAS determinism have not been measured.
